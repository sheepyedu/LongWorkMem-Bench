# 五套基准如何把难度变成可观测结果

供 Work 出题人选择设计机制。下列“W4 采用”均为本项目建议。上游的 L3、L5、应用数、工具数可用来标注任务结构；最终得分仍由模型是否正确完成具体工作决定。

## WorkBuddy Bench：从表间关系，到带时点和权限的状态

Office 轨道共 50 题。GitHub 提供运行框架，题面、材料和 verifier 在作者发布的数据包中。以下两例均可在 Office v1.0 包内按题号定位。[上游框架](https://github.com/Tencent/workbuddy-bench) · [Office v1.0 数据包](https://huggingface.co/datasets/tencent/workbuddy-bench/blob/main/wb-bench-office-v1.0.tar.gz)

| 已核对的样本 | 怎样增加难度 | 怎样入分 | W4 采用 |
|---|---|---|---|
| `procurement-reconcile-L3-015` | 从入库编号推回订单，跨两表匹配，区分数量差异、金额差异与两种单边缺件，输出多页工作簿 | `tests/grading/eval_core.py` 检查分类页、各类 ID 数量、指定 ID 的归类及汇总；`test_verify.py` 将独立检查参数化。该题另有 `judge.yaml` 对内容一致性的语义 rubric | 检查对象、分类和明细汇总之间的关系。能全量校验的收件人与条款做全量比对；汇总页存在只能说明产物存在 |
| `effective-control-state-L5-036` | 给定日期、站点和角色，合并基础规程、签署附录、培训资格、追溯生效的通知、草案及已归档版本 | 对角色覆盖核对键集合及字段值，并检查培训待完成的目标角色没有被错误覆盖；对追溯处置核对受影响记录及具体字段 | 把“谁有权改、何时生效、改到哪个对象”写成可重放状态；用正例和相邻的未授权对象一起验收，按业务后果分配权重 |

上游的字段存在、值正确和汇总一致有时都能被同一条记录影响。W4 先定一个业务结果的最高分，再分摊到字段。能由业务事实裁决的主分使用程序。题号代表两道不同的题，不能把它们的分数差解释为单一难度因素的实验效应。

## OdysseyBench：在历史里给出约束，让不同应用消费同一事实

OdysseyBench+ 有 300 题，Neo 有 302 题。论文按所需应用数分层。Neo 将子任务和约束分布到多日对话；生成阶段模拟历史，评测阶段让代理在 Docker 应用中执行，保存最终文件系统。定制验证组合精确匹配、模糊匹配或代码执行，全部条件满足才计整题通过。[论文 §3.1–3.2、§4–5](https://arxiv.org/html/2508.09124v1)

Neo 的 `3-1/0` 要把 Excel 项目活动整理成 Word，再给 Alice 发摘要。历史事实包括活动数与两项优先活动；公开 evaluation 检查文件存在、文档中的关键词及 Alice 邮件中的关键词。这份配置能检查三个应用之间的部分传递结果，对每项活动的日期和内容却没有逐行断言。W4 让每一轮真的产生动作，并把“活动数”式的检查替换为客户×产品×版本×条款；跟踪实际冻结附件，记录哪个字段错、错在何时。整题通过率仍可作为严格的补充指标。[原题及 evaluation](https://github.com/microsoft/OdysseyBench/blob/3389881fa9e1dbc6e13c5b0706da8007e88d09d4/tasks/3-1/subtasks_neo/0.json)

## 三项补充机制

| 基准 | 原设计与计分 | W4 采用 |
|---|---|---|
| WorkBench | 五个数据库、26 个工具、690 项办公任务。需要选择并串联动作，最终用数据库中的预期状态变化验收，也可识别误发给错误对象 | 用冻结附件和正确收件人的日志验收投递。拟稿、投递、确认是三种不同的状态。[原论文](https://arxiv.org/abs/2405.00823) |
| SWE-Milestone | 连续里程碑上同时追踪新增需求测试与已有行为的回归。论文分别定义 recall 与基于测试状态转变的 precision，并结合两个指标；构题时重复执行以筛查不稳定测试 | 同场引入局部新规则，同时验收受影响对象和应保持对象。正式计分使用 W4 业务权重；参考状态和多次确定性复放用作评分器开发测试。[论文 §4–5](https://arxiv.org/html/2603.13428v4) |
| τ-bench | 代理须在业务政策下操作 API，终态与标注目标状态比较。pass^k 衡量同题重复 k 次均成功的可靠性 | 将全成功可靠性作为补充报告。W4 有部分分，另报告每场分数、题内波动和模型间分差；一次满分只代表一次成功。[原论文](https://arxiv.org/abs/2406.12045) |

## 本仓已有的反例

C1 两种 Codex 权限提示下各跑一次，同一实例分别得 32.95 与 100。首场轨迹表明模型误判工作区不可写，但两次独立生成不足以量化提示修正的因果效应。S1 有模型凭中场摘要取得满分，四场 GPT 实测都没有原生压缩事件。历史双模型批次还包含提前签收和试跑预算截停。因此，应用得多、轮次长或四场总分差得大，都需要回到逐个业务结果和相同运行条件验证。[GPT 四场实测](../../../../docs/results/codex-gpt61sol-20261127/) · [旧批次的分差归因](../../../../docs/results/advanced-audit-20261127/)
