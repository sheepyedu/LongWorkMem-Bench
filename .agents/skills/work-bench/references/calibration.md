# 固定实例重复试跑与发布决策

设计时记录目标人群、可接受成本、一个有业务意义的最小差距（例如能否独立完成一整类历史纠错）、准备比较的模型对和主要分项。开发期调难度、修工具或改权重后更新条件标识。正式批次冻结材料、评分器与预算；跨模型的工具面、时间和外部事件一致。可交错运行模型顺序，避免把服务时段差异当成模型差异。

每行是一次独立会话，CSV 表头为：

```csv
task,instance,condition,model,run,status,score
demo,17217-A,public-v1-docker-h1,A,1,complete,68
demo,17217-A,public-v1-docker-h1,A,2,complete,72
demo,17217-A,public-v1-docker-h1,B,1,complete,59
demo,17217-A,public-v1-docker-h1,B,2,complete,61
```

```sh
python .agents/skills/work-bench/scripts/calibrate.py trials.csv --near 95
```

condition 应绑定任务及评分版本、工具/Harness、上下文策略、推理档、解码设置及预算口径；model 绑定实际模型版本。工具修正前后的 C2 即使满分相同，也应放在两个 condition。同一模型更换业务种子要改 instance。run 是独立运行 ID，同一原作答重评不会增加样本量。complete 与按事前规则可客观判分的 participant_failure 均计入；infra_error、budget_stop 留空分数并计入终态分母。不同中断率会造成完成者偏差，报告覆盖率、观察到的部分进度及缺失原因，高中断条件暂缓排名。

工具分层输出有效数、尝试数、均值、最小/最大、相对均值的负/正偏差、极差、样本标准差及两端占比。near=95 仅表示统计 ≥95 和 ≤5 的比例。示例 A 的均值 70、偏差 −2/+2；B 均值 60、偏差 −1/+1；A−B 的均分差 10，所有已观测跨组组合之差为 7 至 13。该区间描述样本中单次成绩可能如何交错，不是置信区间。单次运行只有一个观测，标准差与重复性未知。

模型共享业务实例，不意味着 run=1 天然配对。工具在各固定实例内按独立重复计算均值差及标准误 sqrt(sA²/nA+sB²/nB)，单侧不足两次则留空；共享随机外部扰动的真配对实验应另按配对差统计。多个实例汇总时，先在共同实例上算模型差，再等权平均；需泛化区间时以**实例**为单位配对重采样，在实例内保留两模型，重复数允许时再在模型内重采样会话。只有一个实例或极少重复时不据此宣称总体排名。

**决策示例**：两模型差 8 分、各自极差 25 分，先看原子项和错误轨迹。若一个工具参数偶发拒收，修接口并重跑受影响条件；若 20 分取决于一次文本包装，把验证改到语义并重放全批；若同一模型确实两次选了不同撤回范围，就保留真实波动，追加独立重复。另有两模型在所有实例稳定满分时，优先设计反事实分支及简单策略对照。降低方差与扩大模型差都需要由新数据验证。

对事先定义的二元交付成功标准可附 τ-bench 的 pass^k：n 次有效独立尝试有 c 次成功，n≥k 时用 C(c,k)/C(n,k)，c<k 时为零。它反映连续可靠成功，与“尝试 k 次至少成功一次”的 pass@k 不同。二元门槛与 k 在试跑前说明，连续分及原子证据仍保留。
