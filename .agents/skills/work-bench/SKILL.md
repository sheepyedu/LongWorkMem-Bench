# 工作场景长程记忆出题与评分

用本技能产出三件可验收的东西：**一张跨轮依赖表、一份能从冻结证据重放的分数表、一份能决定保留或改题的试跑报告**。先读[五套基准的原题和评分机制](references/benchmarks.md)。与出题人确认场景后，再实现正式题面与 Docker。

## 1. 从晚期决策倒推早期材料

挑一个真实岗位在后期必须执行的动作，例如向客户解释旧承诺并补发手册。逐个拆出该动作依赖的事实，写明对象、业务时间、生效范围、来源和实际回执。区分批准时间、生效时间、发件时间、签收时间。公开规则要能裁决多份材料冲突时谁优先。

为每条依赖填一行：

| 对象及业务问题 | 首次出现 → 首次使用 → 延迟使用 | 何时更新或失效 | 晚期读取的证据 | 哪个评分项会翻转 |
|---|---|---|---|---|
| 海州 A 的换机期限 | R2 批复 → R4 首发 → R8 新网点发件 | R9 书面验收后切换；同客户 B 沿用原有通用条款 | 当时有效批复、冻结附件、截止日内签收回执 | R8 应继续执行 7 个工作日；R12 应执行 10 个；R15 对 R4 回溯仍为 7 个 |

让一个应用产出的**真实对象**成为下一个应用的输入，例如草拟的手册经过批准后投递，系统冻结实际附件；后来替换同名文件不能更改旧邮件。困难项可来自局部替代、待办跨轮、时点回溯或自身错误后的补救。每加入一种困难，指出哪两个看似合理的操作会导致不同、可检查的后果。若只增加行数或应用数而答案与动作不变，先保留较短版本。

## 2. 在同一场内做前后对照

W4 采用一条连续会话。用同一条款安排 R4 首次执行、R8 隔轮沿用、R12 局部变更、R15 追溯旧件。选择真实的新订单、新网点或客户异议触发后续工作；晚期题面只给当前委托，不复述早期答案。保留一组应更新对象、一组同类但不受影响对象，以及来自上一班的固定待处理案件。模型可以用文件、索引、脚本或笔记。

为每条依赖登记经过的轮数、任务切换和**实际观测到的**原生压缩。累计输入、缓存命中、单次峰值与交付分各自报告。无压缩时，跨压缩保持率记为无观测。前后轮次能定位错误出现的位置，归因到压缩还需要更强证据。选用更多轮次的条件是出现了新的业务依赖。

## 3. 先确定计分单位，再写检查代码

1. 按业务结果预分权重，再在组内按案件或独立断言分摊。固定案件清单、权重、判定时点和分母。批次有 100 行也只使用该批预定的权重。对成组或重复记录，按主键、值和重数核对，多发、少发和错发均可定位。
2. 每个断言写明输入证据、参考值的独立计算方法、等价表达、满分及失败原因。参考规则取自已发布材料；实际动作取自宿主冻结附件、邮件日志和带业务时点的回执。业务单位、收件人和日期要精确。对开放文风建议只留诊断意见。
3. 分开计首次处置和后续补救。第一次发错仍扣发布分；后来准确追溯且实际补发，可拿对应审计与恢复分。发送覆盖率在固定应发人群上计，恢复在明确存在的差错上计。给所有模型相同的期初遗留差错，避免“没有操作就没有风险”得高分。个体额外制造的差错不能扩大主分上限。
4. 总分可写为各业务组「权重 × 该组正确断言权重占比」之和。逐项保留期望值、观测值、证据位置、所得与满分。状态项按真实世界判；模型自报“已发送”不能替代回执。格式歧义先按公开规则处理，评分器崩溃或输入损坏标记技术异常并复评原快照，预算截停单列已到达阶段。
5. 从同一轨迹另算延迟保持率（首轮正确且规则未变者为分母）、应改项正确率、未改项保持率、历史三项正确率（应发、实发、已签收）和恢复率。公布分子/分母；空分母记 N/A。这些切片用于解释主分，不再叠加奖励。

## 4. 在试跑前找出评分器会错判什么

| 测试 | 预期结果 |
|---|---|
| 金标、等价格式、自然日替换工作日、同字段两种矛盾承诺 | 前两者逐项同分，后两者只影响相应内容项 |
| 改一份早期批准；保持其他外部材料一致 | 参考解只在该批准覆盖的客户、时段和下游动作上翻转。作为开发单测执行 |
| 实际发错后改写磁盘同名文件；截止日之后才签收 | 历史附件仍是发错的版本；晚到回执不能算作审计日已经签收 |
| 空交件、只有模板、永远用最新版、全发、全不发、重复提交 | 标出每种简化策略具体能拿多少分；多发或堆关键词不能跨过关键业务项 |
| 同一冻结状态重放两次；同一事务重试 | 分数及证据逐项相同；可重试的工具按其公开幂等规则处理，真实重复发件留下对应记录 |

## 5. 用试跑决定哪里需要加难

固定公开实例、镜像、题面、评分版本、工具权限、Harness、模型版本及推理档；每次新开独立会话。开发阶段可先用两个模型各跑 3 次筛查，再针对不确定项增加重复。请求预算只属于试跑条件。冻结评分规则后以新作答或预留实例验证；调过权重的同一批轨迹只用于开发回放。

| 观测 | 先诊断 | 改动与复验 |
|---|---|---|
| 多个强模型反复接近满分 | 哪些高权重项用“照搬最新表”也能过？是全题饱和还是某一组？ | 保留基础题，增加必须区分当时承诺、实际履约、当前义务的进阶案件；用正确、过期、误发三条路径重放 |
| 同模型重复波动大 | 列出拉开最高/最低场的分项、首个分叉和后续级联；先查权限说明、超时、解析、请求截停 | 修复环境或等价解析后复评原证据；若确为模型差错，公开波动。把多处由同一个错字段触发的重复扣分合并为一次业务后果 |
| 两模型均分接近 | 查看分项是否互相抵消、简单项目是否占过多分、样本是否太少 | 按预定的业务组报告差异。在两者确有不同处理策略的环节增加独立案件，保留正常路径和回归项 |
| 加检查点后极差不降 | 判断新增断言是否只是同一失误的多个副本 | 用一处错误的冻结交件实算总扣分；细分能改善定位，降低模型行为方差需另用多次真实运行验证 |

逐模型报告每次原分、样本量、均值、最低与最高、向下偏差（均值减最低）、向上偏差（最高减均值），有至少两场时给样本标准差。极差与方差各列。模型间报告同条件均分差及分项贡献，检查去掉单场后方向是否反转；多实例按实例配对，保留实例和运行两个抽样层次。少量重复只支持初筛。若差距小于常见的题内波动、仅一次触顶或排名随一场反转，结论写“当前证据不足”。保留真满分、真低分和预算终止记录。

交付时附依赖表、权重与断言表、正反例回放、真实试跑与成本、仍无法归因的失败。每次改版本记录动机及前后分项，正式测试前锁定规则。
