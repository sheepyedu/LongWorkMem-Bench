## W4 开发中值得复用的回归检查

1. **验排序。** 先声明要测谁的结果、在哪个截止日兑现、证据从哪里来。冻结前运行“计划正确但忽略部分受理”“只取最新版”“错误后按真实历史补救”等策略。W4 v4 单场有 42/48 个客户日达标，综合分 85.51；不理当批回执的对照只有 29/48，却得 91.76。用相同冻结证据复算新旧口径，核查正确执行者是否排在前面。[原场及策略](../../../../docs/work-task-design.md) · [纠正排序的实测回放](../../../../docs/results/w4-promise-20261128/)
2. **限制误扣传播。** W4 v3 的说明段重复时限标签，使首发和后续补办共误扣约 9.58 分。先用成对样例拆开正式字段和等价说明，再验证相互矛盾的明确数值仍会失败。冻结原分，单列修订合同下的同件复评。[格式敏感性](../../../../docs/results/w4-night-20261128/)
3. **明确报告截点。** v4 单场有 6.0125 分涉开班/办后时点，4.1667 分涉全案/变化清单。交付规程写清覆盖范围和时点；一格错误只影响一个字段，一列缺失不应清零同表其他列。柜面真实受理与客户函先后顺序由事件序列独立核验。[局部变异](../../../../docs/results/w4-quota-20261128/locality.json)
4. **验证环境真的按业务日换班。** Colima 曾出现旧路径仍能 stat、读正文已失效。每次发布先对容器可见目录内容求摘要，并实际尝试读取已撤文件。冻结历史附件，按原查询时已到达的事件前缀重建回单。解析器或 Calc 基础设施失败时保留交件并补评。[挂载检查](../../../../docs/results/w4-night-20261128/mount-check.json)
5. **复核证据的单位。** 逐客户日兑现率、每客户全部截止日均兑现率、首错后新阶段正确率分别报告。首次错误不追扣后续已纠正案件；几处表内复制不应重复代表一个业务损失。原子项之间有关联；单个错误扣分较小不能替代跨模型和同模型重复试验。
