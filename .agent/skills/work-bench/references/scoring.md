# 可执行的客观评分合同

宿主先冻结每个阶段，再由独立适配器从业务数据库、真实回执或干净重跑结果形成标准观测。参考侧从工单与当轮前态独立得到期望值。涉及恢复的组可读取模型**已经造成的前态**，再根据规定的业务动作计算唯一目标差量。保留原始输入、实际观察、权重版本和每一项分数。

下面是开发示例。两个收件方已收旧版，晚期只撤回 B 的批准。首组验最终状态，次组验应有的唯一更新。为了让“零投递”可解释，保护 A 的部分只能来自预先定义的兼容权重，恢复组用实际需要的通知作分母。

```json
{"version":"withdraw-demo/1","groups":{
  "state":{"weight":60,"expected":{"A":"approved","B":"withdrawn"}},
  "notifications":{"weight":40,"expected":{"B/event-7":{"count":1,"value":"withdrawn"}}}
}}
```

若状态正确却多发了一条 A 通知，宿主观测可写为：

```json
{"version":"withdraw-demo/1","groups":{
  "state":{"A":"approved","B":"withdrawn"},
  "notifications":{"A/event-7":{"count":1,"value":"approved"},"B/event-7":{"count":1,"value":"withdrawn"}}
}}
```

从仓库根运行：

```sh
python .agent/skills/work-bench/scripts/score.py contract.json observed.json
```

示例得 80 分：状态 60；通知组 1 个正确对象，期望与实际并集为 2，得 20。脚本按组定权，总权重为 100，组内每个对象等权；输出缺失、多余、值错误的对象 ID。组的数量和权重由业务定义。此实现适用于有稳定对象键且能规范化为 JSON 的确定性任务。时间戳、单位、浮点容差、无序表、等效 ICS 和邮箱别名等应由该题适配器处理；要给同一对象不同字段部分分，可按独立业务责任拆组。重复投递须保存次数或有序批次，直接覆盖键会吞掉错误。

**缺件与取证失败**：宿主成功查到本轮未提交，传入该组空对象；快照缺失、挂载失败、解析器崩溃则标记基础设施异常，不得伪造空对象。合法输入样例中确实没有应发项时，可用“已完成核对与应交处置”的正向对象描述，另查零副作用。对参评者提交的坏格式，按该接口契约记录交付失败，并继续检查独立产物。私有合同、归一化器与脚本都置于参评沙箱外。现有 W1/C1/C2/S1 继续由各自已验证的评分器复评。
