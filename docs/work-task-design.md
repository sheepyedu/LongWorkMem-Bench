# Work 新题设计：从逐格正确走向跨期履约

## W4 的总分遗漏了什么

冻结 v4 原场为 85.5083 分。取同一份 grade.json 中四个调度日的“柜面实际席位”断言，逐一比较每个客户应得与实得席位，再按客户串起四个截点。下表的第一行来自正式模型轨迹；其余行是用已有公开办理脚本重跑的确定性策略。没有新模型调用。[正式逐项账](results/w4-quota-20261128/atoms.csv) · [对照策略源码](../tasks/w4/tests/quota_controls.py)

| 作答 | 冻结总分 / 100 | 配额正确的客户日 / 48 | 四次配额都正确的客户 / 12 |
|---|---:|---:|---:|
| DeepSeek 正式场 | 85.51 | 42 | 7 |
| 独立正确解 | 100.00 | 48 | 12 |
| 只取最新文件 | 64.88 | 19 | 0 |
| 沿用期初授权 | 68.44 | 23 | 1 |
| 按案号顺序分配 | 80.22 | 22 | 0 |
| 当批假定全部受理、次日再读真实柜面 | 91.76 | 29 | 0 |
| 仅首批错排，随后正确补救 | 98.89 | 46 | 10 |

同一模型在四个截点分别办对 12、8、12、10 案。较高的单次配额正确率有真实依据。总分的效度问题在于，假定全部受理的策略办对的客户日少 13 个，总分反而高 6.25 分。该策略在其余环节使用正确解，不能视作另一个模型或完全不读取环境的策略。

另外，在原场副本上保留全部轮末文件、重置邮箱并按改变后的历史重放，得到 48.4864 分。另一副本保留原邮件和回执、清空十二个轮末快照的内容，得到 21.5917 分。原场重放仍为 85.5083。这两种不一致的交付用于识别证据来源，不能相加，也不能据此把某份真实完成的计划判零。当前模型还有 10.18 分损失与交付时点和清单范围相关。[既有归因及合同修订](results/w4-quota-20261128/)

## 新题方向

**优先：订阅合同迁移后的收入重述与经营模型交接。** Docker 中提供合同与补充协议、CRM 账户沿革、账单与贷项流水、经营工作簿及沙箱发函接口。早期确认合同接续关系与收入定义，中途冻结已上报的季末版本，随后收到补签和撤回。代理需要还原当时的经营数字，另算重述值，发送确实需要的更正函，并交出可在下一季度继续使用的模型。工作簿中预置一个跨表引用错误；具体哪一格有错留给代理定位。合同口径和审批权限在业务资料中明示。

可做一对成本很低的案件：同一集团两个 CRM 编号都显示月费 10 万元。甲客户两条记录对应新旧合同接续，季末只一份在服，年化收入 120 万元；乙客户对应两个独立且均在服的服务范围，年化收入 240 万元。晚期界面刻意相同，早期签署关系决定正确答案。宿主逐客户核冻结值、重述值、生效日、授权收件人和下一期重算；同一笔差额传到多个图表时只归入一次收入责任，图表格可保留为诊断证据。

**另两个备选。** 一是设备替代料切换与在途履约：将签署的替代关系绑定到客户、批次和生效日，模拟部分到货与在途订单，核按时足量交付、未经授权替换的数量及欠交天数。二是并购交割价调整与留置款释放：在同一数据室中保留原预测、双方签署定义、银行回单及晚到调整，核每项调整归属、截止金额、可释放款项和实际付款；等价分录组合按净额及受益人验收。三题均可用文本接口，无视觉门槛。

## 评分及校准

- 主指标预先选客户可观察的结果，例如截止日前实际兑现的客户日占比，并同时报告未兑现数量及持续时间。将每客户跨期全程正确率作为严格诊断，另报纠错后新阶段的履约率。纸面分析、计算模型正确性和真实执行分别列示。
- 做一对仅改变早期有效授权的历史，保持晚期可见输入相同。两个历史应翻转一项具体处置，其他客户保持同样结果。源规则公开、参考账独立重建、合法等价解均可通过。专家独立办理若有不同合理解释，先修任务合同。
- 冻结前做评分反例。正确计划但无实际办理、过期依据但总额碰巧相同、把款给错客户、先错后正确补救，应在对应的业务指标呈可解释顺序。回归中进一步验证排序，不只验证金标 100 和空交 0。
- 冻结后在同一实例、同一 Harness 和相同权限下，对两档模型各做独立重复。30–70 作为预先指定的开发模型均分参考；同时看客户级分布、同模型极差、模型间差及其是否由单一客户驱动。本次只有离线研究与反事实，尚无新题难度或跨模型区分度的实测结论。
