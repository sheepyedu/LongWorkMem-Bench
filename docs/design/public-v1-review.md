# public-v1 固定实例与审查结论

**适合作为有客观产物评分的三题研究原型。独立模型能力排名、主动上下文管理收益和真实工作场景覆盖仍缺直接证据。** 旧版 24 场提供行为观察。新版已经过运行器、容器、评分器和历史回放验证，新版的模型成绩需要重新作答。

## 每个人做哪一道题

三题共用公开业务种子 **17217**、版本 **A**。17217 是先前预设列表中的第一个，选择规则与模型分数无关。题目生成器用它确定采购与工时记录、签发人、赛事公文和顺序。评分器读取同一场 manifest 重建标准答案。C1 的新来件复跑从同一实例确定性派生，所有参评者遇到相同的复跑用例。重复评分不用抽签，也不调用模型。

| 题目 | 公开运行条件 | 客观验收 |
|---|---|---|
| W1 | 八级、九轮；Docker 办公室，跨轮保留文件和邮件，交付截止为轮末 | 采购、薪酬、邮件、预留按实际快照计分；工资簿要能在 Calc 改值重算 |
| C1 | 三级、七轮；同一 Docker 工位；第 5、7 轮换班，第 2 轮签发通知在第 3 轮撤回 | 按轮末代码和业务交件计分，为新来件复跑。输出必须包含当期规定的数组，零行也须明确交付 |
| S1 | 十区八班；无网络 Docker 文本引擎；第 40 轮结束时保存模型的 note，第 41 轮启动新会话 | 核对登记字段和实际订单；宿主从原始回答重放全部单据，检查换班首请求 |

同一题、不同模型或独立重复均使用相同输入、配置及新运行目录。冻结指纹覆盖 W1 九轮、C1 七轮、S1 公共规则与八十轮材料。S1 指纹使用空摘要占位，参评者此前实际写下的摘要、交付和模型输出属于运行结果。复现还需固定代码提交及运行环境。业务种子不会固定模型采样、服务端版本或缓存。一个固定实例能回答同题表现；同题四次重复衡量运行波动；替换种子衡量对新实例的泛化。三种统计必须标明分母。[材料指纹](../../tests/public-v1-materials.json)

## 算力预算

公开协议默认不限制每场模型请求数。历史 W1 的 350、C1 的 180、S1 运行器原有的三倍赛程预算，均为试跑参数。使用者可显式指定 `--limit N`；实验被截停时保留证据，当前协议不给完整任务分。完整但有显式上限的运行也标为实验条件。W1 的按轮限批、C1 的第二次 shell 即取件改为自选诊断。业务上的轮末冻结、换班、单据格式重交、工具进程超时及服务方的上下文窗口应在相同配置下比较。供应端超时缺用量时，已观测 token 是下限。

## 旧批次的范围

每组包含四个不同实例，C1 的 A/B 随种子配对。总 token 等于上游已知输入加输出，缓存读取已包含在输入中。每组均值的负偏差为最小值减均值，正偏差为最大值减均值。模型间差值逐种子先相减，再平均和取极值。两类极差都受小样本影响。C1 原表保留千问预算终止的 14.15；只看双方均走完的三对，DeepSeek 和千问均分为 45.33 和 37.89，差 7.44。剔除终止场也会造成选择偏差。S1 包装层复算仅作敏感性分析。[完整精确统计](../results/advanced-audit-20261127/dispersion.csv) · [逐场原数](../results/advanced-audit-20261127/runs.csv)

## 严格审查

| 尚缺证据的主张 | 原因 | 达到该主张所需的验收 |
|---|---|---|
| “主要测到长程记忆” | W1 的 Excel 能力、C1 的实现能力、S1 的多区查找都能影响结果。摘要交接由 Harness 强制发生，不能据此给主动整理能力打分。 | 对同一晚期交付配四种前置条件：完整历史、必要事实补齐、移除关键事实、代理自写交接；比较仅由早期事实翻转的评分项，并记录后续请求是否真正采用整理结果。 |
| “覆盖真实超长工作” | 当前只有三题，其中 S1 是受控模拟；旧批单场 50–180 次请求，1.01–13.82 M 已知累计输入。累计输入包括反复传入相同历史。 | 在不同组织、材料格式和流程上增加独立任务，补跨应用操作和真正的无关任务切回。逐题报告单次峰值、首次压缩位置、跨压缩依赖、恢复情况与成本。 |
| “模型排名可信且可泛化” | 旧批次没有固定同一题面独立重复，且有预算截停。公开固定实例及仓内参考代码适合复现，也可能被针对性优化。 | 固定实例多人可复现；另行预注册盲测集、独立重复与匹配算力条件，报告题内和题间方差。测试新版本时冻结上游模型、Harness、工具权限及缓存口径。 |
| “跨 Harness 都能复现同等难度” | 当前主要经 Claude Code 适配器运行。宿主 Calc、底层镜像、工具输出长度、供应端推理设置都可能影响机会和成本。 | 用第二种 Harness 跑同材料、同权限、同冻结点评分；记录镜像和依赖版本并做跨机重复。对评分器增加独立实现、语义等价提交、单点错误和评分故障对照。 |

在上述对照完成前，发布时宜分别给出“工作产物分”“有历史依赖的检查点”“实际上下文管理事件”和“成本”，避免用单一总分代替四个结论。

本地验证记录：110 项自动测试中 108 项通过，2 项容器集成另行运行通过；C1 的 14 项测试另以真实 Docker 模式通过。正常入口的离线传输检查完成 W1 九轮、C1 七轮、S1 八十轮。W1 和 C1 的测试客户端每轮发出五条 shell 命令，未交业务成果，因此零分符合预期。发布的材料指纹在不同 Python 哈希种子下复算一致。CI 工作流可在后续推送和拉取请求时重查材料、计量表和 S1 容器。
