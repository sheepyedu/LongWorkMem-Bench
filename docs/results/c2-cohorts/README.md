# C2 客户迁移版 · 构建验收

在同一 Docker 工具链上执行六条脚本轨迹。每条均经历十次分轮到件、真实客户签收、回执归档、故障注入、数据盘恢复及轮末冻结。依赖完整工作区的现场验收与仅给代码和受控业务输入的重放分别取证。没有使用模型评委。

| 脚本控制 | 得分 | 对照解释 |
|---|---:|---|
| 正确参考实现 | 100.0000 | 全部 697 项通过，重复执行逐项复现 |
| 全程空操作 | 0.0000 | 旧门户和宿主注入的签收不构成模型交付 |
| 全部改用最新客户标识 | 61.4194 | 新报名正常；旧报名改名，使客户端将部分更新当成新邀请，后续差量与追溯继续受影响 |
| 忽略局部撤回 | 81.6891 | 前六轮可完成。后续用错已撤回授权，波及计划、恢复与客户答复 |
| 恢复程序始终读故障前缓存 | 95.8095 | 正常导出仍可用；向已收客户重复通知，换真实签收状态后差量程序继续给错答案 |
| 历史程序只读工位内已存回执 | 94.5500 | 可以复现自己交的客服文件；只改变一个客户的签收，程序无法相应改变实收与未结状态 |

每一分都可从 [参考清单](reference-items.json) 找到权重。不同作答可能有不同的应补件与实收，实际计算使用该条轨迹的真实前态。[全部故障对照的扣分明细](deductions.csv)记录各自的期望和观测；[逐轮分数](controls.json)列出得分和通过项数。697 项共享十轮业务依赖，不能当作 697 个独立统计样本。单项上限不限制一个身份设计错误造成的多端、多轮业务后果。

**细项实例。** 第 3 轮，旧客户的报名关联与旧邀请页分别判定；第 7 轮，改变 D 的签署附件后，D 的撤回结果须改变，C 的结果和第 6 轮仍有效的临时批准须保持。第 9 轮，分别核对 D 收到的事件、是否多收、是否按事故原键恢复。第 10 轮，给一个客户答复的 pending 写入字符串，集成测试要求只失去这一个字段分，其他客户、该行实收时刻和历史程序的分数均保留。

**成本与适用边界。** 用户轮次固定为 10。活跃业务只用两个日期和两门课程。额外对照发生在宿主复制的工位上，模型不会收到这些请求。旧 DeepSeek 十轮轨迹只有 R1 分页合同兼容，复评为 **4/4**；其余 96 分缺少新客户、新工单与故障恢复证据。[旧 R1 回放](historical-paging.json) 构建验收后已补充[首次真实模型盲测](../c2-cohorts-pilot-20261128/)，该场得 93.60 分。模型间区分度和同模型波动仍待多场验证。

各对照可用 `python -m tasks.c2.cohorts.tests.controls MODE` 本地重放。MODE 依次为 reference、noop、latest-identity、ignore-withdrawal、trust-stale-cache、fixed-ledger。测试前设置 C2_TEST_ROOT 并准备镜像。[题面、工具、各轮权重与正式运行入口](../../../tasks/c2/cohorts/)
