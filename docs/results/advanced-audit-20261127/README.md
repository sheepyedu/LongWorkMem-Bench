# 24 场实测：平均分的偏差来自哪里

这里分析三道进阶题在提交 `67a20d0` 下的 24 条原始会话。每题共四对业务实例，种子依次为 17217、17219、17231、17239，C1 版本为 A/B/A/B。两个模型在同一种子遇到相同材料。四次换了题面，只有一次作答对应每个“模型 × 实例”；这些数据无法估计同一模型重做固定题面的随机波动。

### W1：两个模型的低分发生在不同环节

DeepSeek 最低场的预留只有 **4.00/20**，第 3 轮的 36 个预留案没有一个完整正确；资金交接仅 **0.33/12**，个人工资明细正确 **0/48**。最高场的采购为 **16.50/18**、预留 **18.89/20**，工资仍只有 **4.08/20**。工资在多场都难，最高与最低之间更大的差距来自预留和采购。

Qwen 最低场在第 1 轮用完四批共享盘调用，把正式出表列为下轮工作，第 2 轮仍未落盘。采购最终 **1.50/18**、工资及资金交接均为零，但争议预留仍拿到 **14.67/20**。最高场的分数提升主要来自多轮按时交付。八场都发生过原生压缩，单凭这些快照无法把缺件具体归咎于压缩。

### C1：提前取件放大时机差，预算终止压低千问均分

旧实验在每轮第二次 shell 后取件，占总分三分之二。DeepSeek 最高场签收 **33.46**、轮末 **100**；最低场分别为 **9.90、87.00**，且在三个保证金截止日把重复申请多记了 **19、34、43** 行。这说明迟交和真正的程序错误都能拉大总分。另一个实例 17217/A 从签收 **7.20** 修复到轮末 **98.64**，只看总分 **37.68** 会漏掉后来正确复用早期授权的事实。

Qwen 最低场在第 5 轮耗尽 180 次试跑请求，第 6、7 轮的 62 个评分项合计满分 57.56，按当时规则记零。57.56 是未到达项目的权重，不能当作它继续作答就会得到的分。只看双方都走完的三对，Qwen 均分为 **37.89**，DeepSeek 为 **45.33**。当前公开配置按轮末交付评分，默认不设请求次数上限。

### S1：DeepSeek 的异常低点来自登记解析，千问的波动来自订单

DeepSeek 在 17217 把 80 个队次都写成“队号 → 正确赛段名 → 四项数组”，旧解析器忽略该层，登记分 **0/30**。同一份回答只展开该包装，登记得 **26.531/30**，订单分保持 **37.812/70**。四场最高减最低从 **29.132** 缩为 **2.982**。这是有原始回答支持的格式敏感性复算；上表保留原判。

Qwen 最低和最高场的登记分别为 **28.031、29.062/30**，订单却为 **50.556、65.287/70**。只看第 7 班决赛配发，128 个配套或送达判断分别正确 **83 个、120 个**。这两场的主要差距确实发生在赛事执行内容上。

## 用全部四场交叉核对

将每个评分大项对总分波动的贡献定义为 `cov(大项分, 总分) / var(总分)`；总分取未做末位舍入的阶段加总，各项份额相加为 100%。该量描述本样本中与总分共同波动的部分，并非独立因果效应。W1 的过程分合并九轮，C1 采用已加权分项。

| 题目 | DeepSeek 最大贡献项 | Qwen 最大贡献项 |
|---|---|---|
| W1 | 争议预留 **39.5%** | 九轮过程交付 **43.3%** |
| C1 | 提前签收 **85.1%** | 轮末交付 **75.4%**（含预算未到达项） |
| S1 | 登记 **96.5%** | 订单执行 **90.6%** |
