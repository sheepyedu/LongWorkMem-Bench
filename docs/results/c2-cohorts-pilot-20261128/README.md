**R7 的解释边界。** 追加诊断只运行第七轮的冻结程序，固定代码和初始数据库，分别用原签署附件及只改变 D 时刻的附件测试。对每份附件，一次导入 R7 累计材料均通过 24/40 个诊断断言；按 R2、R3、R6、R7 顺序导入，四次导入退出码均为 0，两份附件均通过 40/40。正式评分探针的空起点使用的是早期备份，所以诊断数与正式分项另列。正式场按原规则计 93.60。这 2 分揭示了从累计包重建历史的限制，不能单独据此断言模型在真实会话中遗忘了撤回规则。

**遗留测试与隔离。** 在未被参评模型修改的工位中独立运行遗留测试，初始状态已有 3 个测试文件报告失败。回填上一版本的归档交付件后，仍有 2 个文件失败；部分断言沿用旧数据数量。本场任务主分取自独立评分器和真实签收日志。审计器对齐供应商请求、工具往返、原生会话及宿主签收，未报告异常；检查未发现模型获得隐藏评分项的证据。三次被客户端拒绝的工具尝试保留在轨迹中。

与前版 DeepSeek 单场的 367 次请求、29,947,065 输入和 376,610 输出相比，本场请求少 21.5%，累计输入少 21.4%，输出少 19.2%。题面、业务对象和评分版本都有变化，两场不能估算同模型波动，也不能把用量差异归因于某一项改动。两条超范围通知合计只扣 0.4 分，解释总分时应同时查看实际客户影响。
