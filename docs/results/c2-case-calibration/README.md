## 下一版如何在十轮内提高难度

优先替换现有 R3、R7、R9 输入之间的关系。下面是下一次改题的候选设计。该设计尚未进入公开题面或历史成绩。

| 替换现有内容 | 让两种合理实现产生不同结果 | 客观验收 |
|---|---|---|
| 把 R3 的单张完整映射表换成现役合同与一次只对新订阅者生效的改名。复用既有报名和订阅者数。 | 只按频道取最新前缀会把老客户的单场更新发成新事件。仅保留旧前缀又无法接入新客户。 | 同场、同端，一个已报名客户保留旧 UID，一个新订阅者使用新 UID；旧邀请和后续签收均可验证。 |
| 把 R7 两次同型撤回中的一项换成对 R2 已签条款的有限撤回。R6 批复引用现有区域档案中的一份仍有效附件。 | 当前主表相同，上一层授权不同，撤回后应回到不同的时刻。读全部旧档案和忽略全部旧档案都不能直接给出答案。 | 只交换一个有签章的附件引用；目标端的回退值翻转，邻端和历史版本保持。题面明确优先级、适用对象和有效期。 |
| 把 R9 普通的重复导出改成恢复备份后接续 R8 的一个未确认批次，复用原有超时事故和秋季发布。 | 两份备份可生成相同日历，但收件方有无签收决定能否再次通知。导出器、迁移与恢复代码须使用同一业务身份。 | 两份同形回执只差一次已提交事实。应补发端恰好签收一次，已收端通知数不增加；旧报名仍能关联到正确事件。 |

优先试第一项和第三项的组合。它们让早期的身份选择在事故恢复时真正产生客户后果。保留 R5 的短客服任务，使难度集中在三处代码依赖。新版试跑先沿用原有轮数、对象数量和工具，比较实际请求、峰值输入和耗时；若成本明显上涨，先删去重复生成或核对。冻结题面与评分后，先在固定实例、同 Harness 下选两种模型各独立运行至少 3 场作初筛，报告单模型的最小/最大偏差、阶段分差以及哪一对反事实改变了结果。另抽一个晚期阶段提供正确前态做短对照，帮助区分编码困难与前序状态丢失。
