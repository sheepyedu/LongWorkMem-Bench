# W4 v4.3 · 联席纪要与续签

目标是在同样十二轮、十二案和四站业务里，检验模型能否从多业务来件中保留正确的范围、版本和历史依据。考生可以搜索和写台账。到各个截止点，用柜面实占、客户实际收件及 Calc 重算评分。实例沿用 17217/A。

| 十二天累计，按首次送达计一次 | 4.2 | 4.3 |
|---|---:|---:|
| 初始只读 input 文件 | 640 | 640 |
| 分日来件 / UTF-8 字节 | 29 / 3,497 | 65 / 49,667 |
| 签发材料 | 2 张原件表，2 天送达 | 36 份站点纪要，9 天送达 |
| 现场预约签发条款，含待批及草案 | 48 | 132 |
| 同案同流水的接驳、培训条款 | 0 | 264 |

统计对象为各日 inbox 文件；签发材料是其中的子集。原件借阅后归还，不能按末日目录计数。材料字节数与模型实际读取的 token 分开统计。

例如，第 2 日东港的“潮册”办理现场预约。第 7 日送达的换册单规定，第 9 日起签发的东港纪要改用“岸册”。第 9 日的新件若引用第 2 日流水，仍须接回旧件当时对应的那项业务。第 9、11 日共有 24 项现场续签不重抄额度。其余两册也有自己的额度和签发状态。三种业务在纪要里的次序随议案变化。规则与原件都在工位，评分、探针和开发解留在宿主。

## 离线验收

各策略均从逐日公开材料办理同一实例，通过真实柜面和邮箱交付，用隔离的 LibreOffice Calc 重算。完整解单独解析公开原文。错误策略每次单独启用。客户日列以 48 为分母。

| 程序策略 | 得分 / 100 | 正确客户日 |
|---|---:|---:|
| 完整办理 | 100.0000 | 48 |
| 未办理只给历史引用的续签 | 74.7899 | 34 |
| 只处理原先两批的签发件 | 69.0966 | 32 |
| 误将接驳业务用于现场预约 | 29.0497 | 9 |
| 忽略中途换册 | 85.6210 | 40 |
| 只取最新，忽略资格、有效期等条件 | 57.1399 | 25 |
| 空交 | 0.0000 | 0 |

`python -m tasks.w4.tests.bulletin_controls` 重现上表。首两批原件与登记文件在借阅后撤走，各轮发布后由 Docker 对宿主清单核验，对已归还路径额外试读。旧版正式轨迹在新版代码上逐项复评，仍为 99.9608/100。这些对照说明典型的业务理解错误确实改变客户交付，估计真实模型的均值、方差及区分度仍需要重复观测。
