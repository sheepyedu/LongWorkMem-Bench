## 评分与题面修订

- 第 5 轮两分各对应一项对外可用的交付。客服内容本身正确，在审计中单列；按时交付接口的要求在业务合同中可见。当前开发版增加当轮合同索引，方便发现新增的接口文件。
- 第 9 轮的 0.3529 分有题面歧义。原合同明确按原定日筛选，未充分定义返回字段 day；程序同时保留了原定日和实际日期。补查四个快照、四个频道、所有适用历史版本，按 UID 校验的 1,792 条 UTC 结果全部正确，加验 day 后 1,747 条正确。原始分数照录；这笔扣分不能作为遗忘排期的证据。开发版已明确 day 指原定业务日。
- 给开发版标记 material_revision，补充旧时钟、旧测试依赖与 SQLite 入口说明。复评探针使用独立临时输入目录，支持本机同源镜像，并用错误行局部扣分处理畸形 JSON。损坏 ICS、空查询交付、重复通知、时间等价表示、错误布尔、重复或不可识别的业务键均有测试。正式场使用的原始题面、参数与快照可在归档中复原；澄清版尚未另跑模型。
- 当前 712 个初始文件包括真实遗留代码、数据库和历史交付，但大部分区域档案已过期，可以一次筛掉。主要难点集中在一个规则内核，正确实现会同时带动多个频道得分。若继续开发，应让独立模块各自依赖早先不同来源的有效决定，例如数据库迁移、旧客户端兼容、断点恢复各有一条需要保留的承诺；每条承诺用同形新数据和历史回归各验证一次。在相同工位和预算下补做同模型重复及强弱模型对照，才能判断难度带、区分度及稳定性。
- 本场记录了三次压缩；代码、数据库和笔记均跨轮保留。回执互换能验证程序读取历史的能力。要把成绩差异归因于上下文策略，还需同模型、同 harness、同业务前态的短对照或配对策略实验。
