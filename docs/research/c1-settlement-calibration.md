# C1 工时与保证金校准

每个分数是一场独立 Claude Code 连续会话的百分制加权交付成绩。同一难度、种子、A/B、镜像、工具、阶段上限与宿主评分器分别用于两个模型。DeepSeek 使用火山方舟 `deepseek-v4-1-flash-261017`，千问使用兼容网关 `qwen3.8-flash`。两端均保留默认思考设置。模型只见当前轮委托、陆续发布的业务材料和自己的工作区。

| 实验 | 数据种子 | 每模型会话数 | 公布给委托人的交割约定 |
|---|---|---:|---|
| 一级、二级开发 | 17 | 各 2 | 六轮，轮末取件。一级每批 3 个分片，二级每批 9 个分片并核算 FIFO 分币 |
| 二级签收开发 | 31 | 2 | 六轮，每轮第 4 次 shell 调用结束取件；早交即早取 |
| 二级签收验证 | 41、83 | 4 | 同上 |
| 三级签收开发 | 31 | 2 | 七轮，每轮第 3 次调用结束取件；另有三个版本的短期授权与第七轮历史结账 |
| 三级签收验证 | 101、149、223、277 | 8 | 同上；后两个种子在任何三级总成绩产生前登记为重复验证 |

每场上限均为 180 次上游请求。历史 12 轮题单列。一级、二级开发采用较早的编号表述，两模型都曾错把不同补零宽度的工单合并。随后明确 `003` 与 `0003` 独立，未追改首批试验。第 2 轮签发人是 A/B 唯一变化的来件，R3 起撤回原件。模型可以在源代码、笔记或自己的归档中保留必要信息。三级另在 R1、R3、R4 轮换窗口材料，R7 申请和截止日一致。

判分仅依据宿主冻结的客户取件、轮末交付和隔离副本上的新数据重跑。签收和轮末按 2:1 合成。三级权重在首场三级运行前冻结，前六轮 75 分，第七轮 25 分。三级验证的后半批使用增加了可选直答参数的网关版本；本实验沿用相同默认超时和思考设置。数据集种子是可重复生成的开发研究样本，本报告发布后可用于回归。

三级开发的两个 DeepSeek 运行分别为 92.48 和 79.83。模型能在原会话里咨询已保存的制度，从既有实现直接归档。因此另设七轮换班条件，与连续会话分开报告。在 R1 通告 R5、R7 接班，届时使用新 Claude 会话和新的客户端配置目录，清除网关的历史推理映射，仅交接同一业务工位。两模型取件窗均为两次 shell（可在一次命令中批量阅读或实施）；总预算、题目和评分权重相同。开发用 31，独立验证用 317、419，各含 A/B。在验证分数产生前固定该条件。

## 已定位的问题

- 旧编号措辞确实影响成绩。一级 17/A 千问把不同宽度的工单合并，将原本可能合法的调拨判作同户无效，六轮做完得 10 分。17/B 同模型第三轮纠正编号口径，得 82 分。该开发样本不用于估计后续澄清版的模型差距。
- 在二级四次窗口的 41/B，DeepSeek 的第一、三、五轮末答均声称客户已经取件，对应交割目录实际为空，轮末才有正确结果。83/A 也有提前声称交付的轮次；83/B 首轮主动说明错过窗口。千问 31/A 也报告首轮取件时文件已生成，宿主快照为空。评分依据两次冻结证据。轨迹能确认陈述与事实矛盾，无法据此判断意图。
- 只保存相同空 JSON 原来会因“旧交付保留”得 2.4 分。加入有效交件条件后，空对象得 0；调换合法数组顺序仍可得分。独立解按区间追踪 FIFO、按日期展开保证金制度，在新路径、新 ID 和新方案上可得 100。
- 二级开发 17/A 千问用完 180 次请求，在第五轮终止，已经写出补正交件。计入中止现场，原来的 18.65 分复评为 38.51 分。第六轮未收到，仍得 0；末次工具回执因上限没有下一条上游请求可供比对。
- 生成器会产生同组多张撤令，但签名交替，天然来件没有触发“第二张同样合资格”分支。单列新来件探针补送第二张有效撤令，检查 duplicate 及整账不变，同时保留已冻结的主评分。
- 三级 149/A 的 DeepSeek 在第 72 次回复中给自己的临时复算文件起名 `scratch/guarantee.rerun.json`。第 73 次起，历史消息中的文件名触发了宿主对 `guarantee.rerun` 的字符串报警。首次出现来自模型生成的命令，可逐条回溯。评分代码、权重、标准结果均不在工作区。

两次调用窗口的四场 DeepSeek 验证实得 31.60、37.52、52.48、52.48。为检验较短窗口带来的同分现象，最终对照维持相同七轮、R5/R7 换班、题型、预算与权重，窗口改为三次调用。开发种子 31，验证种子 503、617。两模型都在这个条件的首个成绩产生前启动。各条件分别统计。

两条换班轨迹说明总分差在哪里。两次调用、419/B 的千问在 R5 开始时成功执行了两次工作区 shell，随后尝试 Read、list_files、Bash 等未注册工具。R6 初始化显示 workshop 已连接，每个上游请求均带唯一可用的 shell，代理仍答复工具不可用。两轮未出件。R7 再次换班后完成保证金账，最终得 18.12。相同条件的 DeepSeek 317/B 在 R1、R2 反复核对现有实现，累计耗完 180 次请求；已在第六轮写出主结算与九份归档。计入该实际现场后由 20.75 复评为 31.60，未收到第七轮。两种失败对总分有影响，都保留在样本内。

二次窗口 317/A、419/A 的 DeepSeek 在一份没有可见调拨的历史方案中省略了必需字段 `travel: []`。余额、凭证余量、耗用等仍计相应成绩。该归档的成本明细组合项失 1.36 分；JSON 正常读取，其他归档照常评分。千问三级 277/A、换班 317/A 的 Claude 回执与上游工具参数有 Unicode 转义差异。逐字比较，分别为正则中的汉字区间和诊断用中文字符串，按沙箱实际执行版本计分。

## 当前采用的开发配置

采用三级、R5/R7 换班、每轮第二次有效 shell 调用结束取件，每场上限 180 次 API 请求。317/A、317/B、419/A、419/B 四个独立验证配对的 DeepSeek 成绩为 52.48、31.60、52.48、37.52，千问为 38.13、39.93、47.46、18.12。配对差依次为 +14.35、−8.33、+5.02、+19.40。DeepSeek 均分 43.52、千问 35.91，相差 7.61 分；两个种子各自的 A/B 平均差为 +3.01、+12.21。开发种子 31 的平均差仅 +0.70。

按签收与轮末拆开，DeepSeek 为 19.65、91.26，千问为 9.57、88.59。7.61 分中约 6.72 分来自按时交付，0.89 分来自轮末质量。第五轮两模型在 317 的 470 个授权翻转事件上均能两版同时答对，419 的 476 个翻转事件只有 DeepSeek 完整交件。第七轮按时交付的配对翻转行均为零；轮末的 317 有 360 行只有千问两版均正确，419 的 354 行双方均正确。跨班保留的资料确实能用于正确结账；总分差异包含执行安排、工具选择和预算消耗。两个独立种子不足以证明稳定的模型排名。
