# S1 器材联赛的交接记忆校准

## 预定比较

单位为同一种子、同一开幕史下的整季百分制得分。DeepSeek 和 Qwen 使用相同的 Claude Code CLI、换班位置、简报、表单、交接簿字符数与 32 次上游调用限额。按“DeepSeek 高约 8 个点”解释为两者的整季平均分相差约 8 个百分点。预定将 4–12 点作为描述性的接近区间，同时原样报告差值、每种子的方向和局限。基础 S1 与这个扩展分别报告。

开发种子 134 的两种历史用于逐级试跑。L1 与 L2 均运行；若 DeepSeek 高于 70 分，或已入目标区间但两模型差值尚未落入接近区间，则继续下一档，最多到 L4。若两者第一次均达目标则停止加难。选档先看 DeepSeek 是否在 30–70 分，再在满足区间的已测档中看配对差与 8 点的距离；没有命中时保留偏差。预留种子 9081、12038、46322、71067，每个均有 A/B 早期历史。先冻结选档，再开放上述种子的两模型成绩；留出结果不回流到本次选档。

额外诊断使用开发种子相同的报名表：八轮连续值班、分段交接、仅当前订单、随单补回此前公开的原始公文。补回公文仍需自己识别草案、撤回、生效范围和当时版本。开发条件不计入留出均分。当前订单不提供开幕配置；交接主条件在第 4、7、8 班重置会话，仅带入玩家自己的交接簿。

四档分别有 6、14、24、36 支队伍，簿长 620、420、420、480 字符。每档的预选、邀请、决赛和历史补办分别占 20、15、40、25 分。每队检查两次独立交付，器材和箱签同时匹配才可上桌，领牌员和交接台同时匹配才算送达。队号绑定，允许任意行序。草案、撤回、有效期限的识别通过实际交付评分。A/B 仅翻转半数队伍的开幕器材类别，所有后续公文与抽签订单相同。样本由种子生成。同种子的 A/B 和同一赛季的各队共享材料，分析时按种子聚合。

### 正式比较推理设置（留出开启前修订）

最初的默认推理试验中，14 队 A 的 DeepSeek 在第 4 班连续四次返回 length，每次耗尽 16,384 个输出 token，均无可执行表单；这局标作未完成，保留所有默认设置轨迹。为降低思考预算耗尽对记忆测量的干扰，正式开发选档、留出与三项对照统一使用两家 API 支持的关闭显式推理模式。先前各档全部在新模式下重新起跑。采用原种子、权重及选档规则。先前轨迹独立列为运行器诊断，不能混入新模式。即使有完赛，一律保留该设置两方的全部原始结果。接口探针与逐条审计检查返回的 reasoning 内容和已报告的 reasoning token。

### 第一版留出与第二次独立校准

第一版开发 L1/L2/L3 的 DeepSeek 与 Qwen 分别为 57.19/66.25、32.68/0、23.54/0，按既定规则冻结 L1。此前留出的四个种子上均值为 63.20/12.03，相差 51.17。缺失具体队伍信息时频繁照抄示例，依赖一次有没有抄下整张底册；这会掩盖时效记忆的差别。

仓单版在每次实际订单旁附同队季前仓单。仓单未经赛季核准，两个开幕史以外的各班所见原件仍相同。报名时有些队伍已更换过字段，随后还有跨班批准、撤回及专项到期。用明确的字段占位说明替换可直接照抄的样例值。每行按两项实际交接分别记分，四项齐全但值有误时接受提交，独立验收两个字段对。保留第一版全部成绩。新版本在开发种子 193、386、517 的 A/B 上从 6 队到 14 队逐档测试，必要时升至 24、36 队。若至少 14 队且本档同时满足 30–70、差值 4–12，则停止；若 DeepSeek 低于 30 也停止。优先在达标且至少 14 队的档中选；其余按分数区间、差值距 8 的绝对距离、档次依次选择。冻结后只在全新种子 23011、30493、46703、58427、61781、70297、81919、94603 上评估，每种子双模型 A/B。另用 193 两版跑三类对照。各模型统一关闭显式推理。验收后不再按这批留出调整。

### 逐局核查

- 留出分别审查 131 和 130 次上游调用，均有用量回执。新会话首条请求、公开系统提示、订单、Claude 终端回复、实际上桌与送达字段均与宿主记录核对。没有向参赛模型开放工具、评分权重或答案。5 次格式重提全部成功；包括正文前多了一段说明、缺少 JSON、无订单时传入 null。没有因解析异常丢弃留出对局。按订单检查时 DeepSeek 缺交 4 行、Qwen 缺交 1 行。多报或长度不对的行单独登记；仓单版不会因为一个字段值错误而抹去另一项已完成的交付。
- 种子 61781/A 第 8 班，18 队补邀请赛箱签。两模型都填 68，那是第 6 班批准的新值；邀请时实际为 83。两者均保住送达分。种子 94603/A 第 8 班，DeepSeek 笔记写了四个队该查哪一班，实际提交的订单对象为空，四队均未配发。前者是历史版本错误，后者是执行遗漏。早期试验还出现过凭示例杜撰配置。未发现从评分器读取答案或更改成绩的证据；记录不能证明主观欺骗意图。
- 同一模型共 256 笔留出订单，原样照抄旧仓单的固定策略平均 19.18 分。库存字段对确已过期的 405 次验收里，DeepSeek 正确更新 245 次，Qwen 201 次；当只翻转开幕史便会改变正确器材时，36 笔 A/B 配对中两种历史都填对的分别有 26 和 21 笔。两个统计分母都按实际出现的订单计算。同一队号可能跨阶段再次出现。
- 在“忽略撤回便会改变答案”的字段中两者分别正确 9/16、8/16；邀请专项到期为 9/20、14/20；历史截止为 15/22、9/22。三类可重叠。预选、邀请、决赛、补历史四阶段（满分 20/15/40/25）两模型分别得 13.12/11.60/24.06/13.09 与 13.91/9.61/19.69/10.74。笔记触顶被截短分别出现 3、20 次，含结算后不再使用的末班笔记。分差主要在决赛与历史补办出现，Qwen 对邀请专项到期的处理更好。
- 各赛季、阶段分、实际笔记长度、实交行数、首个错行、上游用量与技术异常记录在 `docs/research/evidence/s1-relay-rollouts.csv`。空的成绩栏为未完成，不参加均分。原始逐轮会话和每次用户提供的材料保存在宿主运行区，各场的 manifest 记录实际代码版本和 CLI 版本。参考领队在 12 个种子的四档双开幕史只靠公开公文和容量内笔记即可得满分。这是可解性上界，使用了程序编码和解码。
