# W1 采购与薪酬进阶题 · 配对校准

## 运行方案

旧版保留为级别 0，历史 Docker 复验中的 DeepSeek A、B 都是 100 分。新题使用同一套九轮办公工具。级别 1–4 逐步增加业务规则，5、6 在四级上提供两种远程窗口，7、8 再加入跨轮授权。前六级采购、财务批准及奖金、邮件各占 40、35、25 分，记忆版分别占 30、25、20 分，另有 25 分预留授权。计分依据是阶段快照、实际重算和邮箱事件。

开发种子 431。两个模型在相同难度、种子、人事变体、镜像、Claude Code 和每会话 350 次上游请求上限下运行。先观察一级，再比较二级。当前校准目标是 DeepSeek 平均 30–70 分、与千问在同题实测中拉开差距。早期曾计划观察领先 5–11 分，按最新要求取消固定差值。成绩表示 100 分制上的部分得分。每对先相减再取平均，调用失败或运行中断单列。

事先保留种子 1733 和 2671，各用 A、B 两种早期人事批复。同一版的公开文件与提示要在两个模型间逐轮核对摘要。确定候选题面和计分规则后再使用这四个验证实例。报告逐对分数、各业务阶段得分和方向一致性；四对的结果仅支持本批样本的描述。

三级沿用二级的四库订单、采购/薪酬/邮件三类分值和工具预算。开发对照的一级、二级首轮中，两模型的采购底稿均得 7/7。三级在同一种子上增加三件可由实际经办人完成的工作：

- 六月底公告凭证库迁移。关账前可以留经办副本；七月售后退货与折让须追到当初的包装、汇率、已签发版本与跨行分摊金额。
- 六月底按有效日期冻结两厂胸牌及工时系数索引。七月原始打卡使用本地胸牌，同号在换班期可对应不同员工。
- 资金岗按两个截点冲抵已付、在途及退回金额。三个支行分别比较送审原件与现额，可出现原件实发、仅补差建稿、账户变更后整包重拟三种处置。首稿附件与真实投递回执分别取证。

四级候选沿用三级关账、跨期归档和资金交接，增加寄售转购的整组唯一认领、季度结转及部分工时追溯，以及有书面授权的跨日核验函。每阶段重新根据当时能看到的资料办理；有多解、缺签或不在窗口的记录有明确挂账路径。四级在两模型中使用相同的字段、权重和业务时点。保留前三档和每个已运行实例。

另设同一四级业务的远程 ERP 窗口条件（级别 5），单独报告。各轮分别允许 9、8、5、5、10、6、12、8、8 批共享盘作业。企业远程桌面对一批命令只收一次作业；批内可任意使用 Python、Calc、多文件和反复核对，邮件、草稿、回复及模型思考均独立。每轮开场告知批数，作业回执显示余量。一个批次用完，当前阶段仍可完成邮件交付和汇报，其余财务工作可在下一次窗口继续。窗口关闭是业务状态，服务调用失败另查。四级仍提供充裕作业时间的直接对照。引入这一条件是为了测量同任务下能否事先规划、合批、保存跨期工具与依据；成绩可能同时受工具效率影响。各轮配额在五级模型试跑前确定，沿用四级相同分项和权重。

为检验窗口条件下单次开发运行的偶然性，另取开发种子 947/B 与 431/A 交叉验证。该决定在首个窗口开发样本尚未结束第一轮时作出。优先选能靠业务复杂度达到目标的无窗口题，窗口条件始终单列；采用哪项进入验证，依据完整开发运行和工作可解性。期望分差是配对的部分得分差，另报满分数、单题范围、正反向次数和按种子汇总。

## 评分与轨迹复核

评分器和题包生成器只在宿主运行；模型只见当前办公材料、历史会话和三个工具。两模型逐轮比公开资料和用户请求的摘要，另外核查上游真实模型名、请求回执、工具调用及阶段快照。同一交付在旧版评分器和统一修订版上复算。修订版将工作簿基线的正确性与从当前有效输入改数后公式能否正确联动分开，增加受限金额/工时单元格以及实际收件人可见范围的检查。权重在开发运行之间固定。

- 一级两模型的采购、工资以及最终获准的两封投递均正确。千问在六月另建了两份未受委托的 ZIP 草稿，邮件权限扣 3 分；这两封都没有发送。DeepSeek 第七轮初版公式出现 `#NAME?`，自行修复后，宿主实际修改 24 份员工工时和两个项目池均通过。文字总结把两类作废与待核版本混称，且把一张后来被覆盖的补正也称作最终生效。
- 二级 DeepSeek 第七轮遗漏 HR-0628，把 E07 在甲、乙的工时分别做成 29.25、13.50 小时；应为 12.75、30.00。两项目总额都守恒，其余 46 个人员项目行、11 张待查票正确。自测改工时和额度没有覆盖转岗日期。第八轮它主动指出错误，随即用改后工资替换已经报送的原件再拟稿；邮件路由正确，实际送审附件没有遵守原件要求。
- 三级首轮 DeepSeek 从相似编号推断未获签的发票已有对应采购行，四个库均受影响。其 288 行中，入库和发票金额分别都还有 260 行正确；实际挂起 24 笔，全部属实，但应挂 80 笔。第二轮收到有效认领后该轮补件正确。千问同题首轮完成全部 7 分。该记录可证实越过了业务授权，不能据此推定主观欺骗。

短窗口候选（级别 6）保留全部四级业务文件与原评分，单轮 ERP 批数分别为 4、5、3、3、5、3、6、5、5。本配置在该条件模型实测前固定。选择依据是五级已观察到首轮代理在一个批次写入完整采购程序，而作者试办中工资首次有一次错误也能在六批内完成。开发仍取 431/A 及 947/B，按完整配对结果比较两种窗口强度；正式验证只采用选定条件。窗口限制只作用于共享盘操作。

## 跨轮预留授权

七、八级在四库采购、季度奖金和资金交接上加入争议款预留。主管在第一轮口头签发六组常设岗位和额度，第四轮仅临时替换一个项目和业务类型，第六轮撤回其中一个库区，并给一家供应商追加仅一天的停办指令。后续清册只给原始案件。第三、五、八、九轮各有 36 条实际申报，两个库区复用案号。第九轮按上一轮真实提交的预留金额补提或冲回。代码与答案保留在宿主机，办公室可以自由记笔记、搜索已开放的资料。

本题型在模型运行前锁定 100 分构成：采购 30、薪酬 25、邮件 20、预留授权 25。四个办理日分别核对项目、岗位、有效批文、处置、金额，每库每案独立得部分分；末轮另核实际追调和历史留底。原有各级仍用 40/35/25。七级使用普通远程窗口，八级使用短窗口。开发先对 431/A 运行，947/B 复核。预留种子保持不变。

中断的会话单项保留。重跑时两条五级 DeepSeek 轨迹恰在工作树同步期间失去办公室，Claude 仍能输出文字并给出正常结束记录。逐轮初始化显示工具数为零，431/A 的第 7–9 轮和 947/B 的第 6–8 轮受影响，整条排除。复测从与各自千问相同的固定源码副本启动。后续运行器在宿主按会话固定六个办公服务文件，正式成绩同时要求每轮真实注册了指定三种工具；缺连接时不把该轮冻结为有效提交。

随后在业务开办日发现 `desk` 栏的 `7084` 与授权中的「岗7084」被分开判定。题面使用「由岗7084办」的自然措辞，两种填写可唯一确认同一岗位。版本 3.2 只在岗位栏接受相同的四位数字，号码不同、多岗混填或把数字当其他批文均继续判错。保留 3.1 的计分代码以复算原始快照；该修订适用于全部模型和实例。

## 九轮交付与评分复核

- 1733/A 的 DeepSeek 在第七轮交付 48 项工资，实际改动项目金额的六次重算全部通过。授权核验函、送审草稿、获准后实发均有相应邮箱事件；它在第五、六轮少交回执登记，这两轮分别扣登记分，实际已发送的正确信件仍获分。
- 1733/B 的 DeepSeek 报称第七轮办结。工作簿中用 `=A2&"|"&B2` 拼项目和员工编号，原检查将引号内的分隔符误判成外部调用。用正、负工作簿复现并区分公式运算符和字符串后，对同一批冻结文件统一重算。该工作簿六次调奖金池只通过一次，整场由 56.7738 改为 57.1309。保留锁定版分数与修订版分数，分别记录在逐场成绩表。
- 2671/A 的 DeepSeek 在第二轮称核验函已全部实际投递。日记确有四封，但它将四个库区的核验函都发到通用应付地址；签件只授权向两个指定岗位投递。第五轮未生成当天业务文件，第七轮实发三件也未落盘，代理如实告知截止失败。第八轮补交了工资件；第九轮按昨天实报数做对 36/36 笔调整。该样本同时出现收件范围错误、真实披露和正确的后续办理。

- 在千问的两个 B 版里，停办案件均投给正确的内控岗位，授权栏填成「签停2950」或「签停8111」。用户原话是「另签停…」，这两种填写均唯一对应当日批文。版本 3.4 在授权栏接受带「签」的同一停办号，保留对错号、混号的检查；两模型全部原快照一起复评。修正后，两模型在两种子的人事变体对照均为应变 20/20、应保持 52/52。1733/B 的千问仍有独立的实质错误，末次 36 笔追调只对 12 笔。

锁定版四对均值为 DeepSeek 64.23、千问 54.08，相差 10.15 分；两处格式修订后的方向与量级一致。两款模型各赢两场，领先均值主要来自种子 1733，种子 2671 的平均差为负。两种子均复用相应的 A/B 业务底稿，因此这四对只说明本次难度和综合表现。独立冷启动实验支持题目依赖早期授权；两款模型的相同人事变体对照均全对，长期记忆能力的模型差距无法由该项单独证实。
