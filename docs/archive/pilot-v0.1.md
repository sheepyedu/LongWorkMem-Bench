## 一、从哪些工作中出题

一题是一条从首个委托到最终交付的完整会话。首版目标约 50 条。抽样时交叉观察下表的工作对象与依赖形式；同题可跨域，只计一次。领域配比、轮数、窗口占用与压缩次数待试跑后决定。

| 主工作对象 | 可作为阶段产物的对象 | 值得测的依赖 |
|---|---|---|
| 文档与沟通 | 修订稿、决议、对外通知草稿 | 新版本替代旧决定，保留仍有效的例外；对外稿使用获准事实 |
| 表格与数据 | 对账明细、分配表、汇总表 | 归属、排除项、暂缓事项和精度规则跨表传递；变更一行后汇总联动 |
| 代码与自动化 | 导入模块、兼容接口、导出脚本 | 继承旧格式和调用约定；新功能上线后已支持输入继续可用 |
| 网页与业务系统 | 草稿、工单、日历、状态记录 | 按记录 ID 修改正确实体；重试保持唯一；仅草拟时不得留下投递事件 |

每题另外标注主线结构（持续演进、跨产物交接、短暂切出再恢复）、依赖生命周期（持续有效、被取代、待确认后生效）与证据位置（只出现于对话、可从源文件重查、可从当前业务状态推导）。同一题可同时涉及三者；自然持续演进的题可全程没有插单。以用户轮数、工具往返、工作量和最大实际请求长度分别描述长度。累计输入与活动窗口占用分别统计。

## 二、出题人如何写一条可复跑的会话

先从原始业务材料和最终要做的决定反向画依赖图，给每条关键边指定来源轮、到期使用轮、有效期间、重查权限、可观察字段和反事实变体。然后写逐轮用户话术。运行控制器只按发布表揭示当前消息和材料，保留同一会话与工作区。用户轮在代理提交本轮答复或耗尽预置轮预算后结束。阶段未达标仍按预定脚本推进；确实缺件时允许代理在后续轮补做并保留两次快照。不得用参考产物悄悄替换代理的中间成果。各策略面对相同业务事件，检查器不给下一轮提示。

**样题 A：报销复核、待审款项与部门分摊。** 下面是拟制的最小脚本，微型数据只用来检查规则。真实压力需要从后续试跑的工作量来验证。公开初始表含 E17（会务，1200 元，默认“市场”）、E18（差旅，800 元，默认“交付”）、E19（物流，300 元，默认“市场”），以及状态为 E19 补件中的附件索引；初始门户没有该批草稿。两份不相干批次作为不得误改的参照。

| 轮 | 代理实际收到的用户请求或新材料 | 轮末冻结和私有检查 |
|---|---|---|
| 1 | “把本批报销记录与票据逐笔核对，给我一份可继续修改的底表。E19 等补件，先别列入可分摊金额。” | C1 保存底表。检查每笔稳定 ID、原额、已确认或暂缓状态；当前可分摊 2,000 元。 |
| 2 | “会务那笔财务确认由交付组承担，只改本批归属；原始台账还要留作审计。” | 保存新的有效决定。变体 B 只把“交付组”换成“产品组”。锁定源台账原文与范围。 |
| 3 | “用刚核过的底表编部门分摊草案，以后补件可以直接更新；给我明细和汇总。” | C2 冻结工作簿。核 E17 归属、E19 未进入可分摊、明细到汇总的关联；改一笔核准金额后重算验证联动。 |
| 4 | “下午先开会。请给我准备三句话汇报，说明哪些已经确认、哪笔还在等，先存草稿。” | C3 核文稿中的当前金额、未决项和草稿状态；保存切走时的底表与待办。 |
| 5 | 返回原任务并释放补件：“物流票据到了，按附件上的核准金额更新原来的分摊表。”附件按 E19 核准 240 元。 | C4 是恢复点。核 E19 从暂缓变核准、差额 60 可追溯、E17 归属沿用上次决定；三个 ID 各出现一次。 |
| 6 | “把本批分摊归档，在审批门户留一条待复核草稿，并把草稿编号写回汇总。” | C5 核明细、汇总、门户同批同额同编号；唯一草稿、投递事件为零、两个参照批次未动，历史草稿按生成时事实核验。 |

A 版本终态为交付 2,000、市场 240、合计 2,240；B 版本为产品 1,200、交付 800、市场 240、合计仍为 2,240。只看总额会让两个版本得到相同分数。两版本末轮使用完全相同的请求与附件，检查器只应在受影响的归属及其下游汇总上改变期望。此例允许重读工作簿；若模型从正确保存的早期决定恢复，业务依赖算成功，证据路径另记。若前轮底表已错，短对照可区分前序制作错误与后续使用困难。

**样题 B：导入工具的兼容升级。** 这条主线可持续演进，无须插入无关工作。

| 轮 | 用户请求 | 可执行检查 |
|---|---|---|
| 1 | “旧系统导出的工单 CSV 还要继续用。请修好导入器，带前导零的工单号按原样保留。” | 冻结代码；旧格式回归集，含 `0017` 与 `17` 两个实体。 |
| 2 | “第二个系统也接进来，列名映射见附件。重复导入同一来源的同一工单只更新一次；两个来源可以用相同编号。” | 合并键应为来源与原始编号；两次导入后的库状态、行数及既有入口回归。 |
| 3 | “给交接同事写一份迁移说明，附一组他们能照着运行的命令。” | 在干净副本执行示例并检查状态；冻结此时代码。 |
| 4 | “现在做按部门导出，沿用之前的导入方式。旧系统没有部门字段，这批放在待分派。” | 隐藏混合输入同时检查新增导出、旧入口、前导零、跨来源同号和重复导入。 |

变体仅改变第二轮的跨来源合并规则，并相应重新生成金标准。使用一组两来源同号、负责人不同的数据，公开稳定的冲突优先规则后再启用合并变体。若工作目录只剩最后一轮指令和原始附件，两种口径都合理，必须从会话或先前工作产物找回决定。

**样题 C：培训改期与通知。** 业务网页给出两场同名活动及不同稳定 ID。第 1 轮请定位指定组织者的那场会并建立邀请草稿；第 2 轮给出场地确认邮件，只改该场时间，外部旁听名单仍待批；第 3 轮暂转去更新会务文档里的路线图；第 4 轮回到门户，请在已有草稿中补入新批准的旁听者；第 5 轮只导出最终清单供复核。检查点分别核验选对活动、时间改动未波及另一场、返回后沿用原草稿 ID、只加入获批人员、没有投递事件。确定性本地站点按种子重置，固定虚拟日期与时区，只向代理提供正常网页入口。短对照给正确草稿与待办，保留同名干扰项和相同末轮请求。可用布局不同但语义相同的网页验证评分独立于点击路径。

一题的发布包包含：初始快照、按轮释放的请求与附件、检查点冻结规则、依赖表、私有断言和反事实种子、参考解与已知错误解、运行与计费配置。私有部分位于代理沙箱之外。表格比较允许合理布局与公式写法；有可重算要求时用固定版本的计算引擎改变输入并重算。文档优先校验实体关系和事实，网页核底层对象和事件，代码用干净环境运行隐藏测试。保存环境版本、时区、随机种子、文件清单及快照摘要；重命名、删除都必须在恢复后的评分环境中重现。

## 三、评分与归因

| 报告项 | 单条会话的口径 |
|---|---|
| 最终完成 | 所有预先公布类别的关键业务断言与副作用约束通过才算达标。总分母为该配置排定会话，预算耗尽计未完成。基础设施错误、缺失回执单列，并同时给有效运行分母及上下界。 |
| 阶段进度 | 各阶段先按独立业务要求算通过比例，再等权平均。阶段内相关的多个单元格断言合成一项。记录切走前、第一次返回提交、最终三时点。 |
| 依赖延续 | 逐条核到期的活动依赖是否在指定产物上得到正确使用，标明已撤销信息是否被错用。主口径覆盖所有预定到期依赖；上游已正确建立的条件分母另报，定位前序错误传播。 |
| 返回主线 | 在有切换的会话，报告首次返回提交正确恢复的项数/应恢复项数、所用请求数，以及后续修复与否。无切换题记不适用。 |
| 质量代价 | 程序化主指标先单列。少数难以机械判断的表达质量采用盲评 rubric、固定评委版本、证据摘录；抽取分歧样本人工核对。评委分及缺失率另表展示。 |

同一事实可出现在阶段进度与依赖分析中，两个指标用于回答不同问题；它不在一个总分中重复加权。先对每条会话算分，再对会话宏平均；同时报告原始分子/分母和配对差，重复种子与若干下游依赖均归属原会话。

上下文编辑按证据链登记：工具可用 → 代理提议（标明是否刚收到提醒）→ 框架接受或拒绝 → 首个实际消费新上下文的模型请求 → 依赖到期时的产物结果。用请求 ID、上下文版本及经规范化的相应片段或摘要核对消费，排除只是工作区文件变动、工具回执回显及无后续请求。一次事件可服务多轮，最终使用是否因该编辑导致，仍需配对干预才能判断。原生压缩记框架事件 ID、前后请求；只见长度骤降标注推定，无法观测记未知。分别记录用户输入、工具结果、模型响应和摘要调用，保留真实请求的命中/未命中/写缓存/输出等提供方字段及缺失原因。

主结果并列报告完成率、依赖延续率、请求数、累计输入、每请求输入分布、峰值占窗口比例、缓存命中与未命中 token、输出、耗时及同价表参考成本。对超时、失败和重试照实计费；同一调用不可把网关和上游各算一次。先展示全部会话，再补充达到相同交付标准的成本；“可接受成本”在正式跑前根据试跑资源与实际用途预先约定，避免结果出来后调价或改预算。

## 四、对照、试跑和扩题决策

1. **先验题。** 先制作 A、B、C 三个不同结构的开发样题。出题人依据源材料生成参考解，第二位核验者仅凭公开题面独立还原有效规则。每个关键断言至少能抓到一份只错该关系的产物，并接受合理的等价实现。相同冻结快照在两个干净环境重评必须一致。有多个合理业务解释时修订题面或断言。
2. **先比较最小策略差。** 在同一模型版本、Harness、业务工具、窗口、原生压缩配置和每题预算下，首轮只做原生与基础 CLM 两组；后者只增加活跃上下文编辑接口及必要使用说明。普通文件笔记与源材料重查对两组同样开放。每题至少两个配对实例/重复，初始矩阵为 3 题 × 2 策略 × 2 次 = 12 条完整运行，作为测量可行性的起点。轮换策略顺序，隔离缓存命名空间或记录冷/暖状态，保留同条件重复的波动。短对照的调用另计。以上是试跑安排。
3. **短对照用于定位。** 选 A 的 C4、C 的草稿恢复点。全新短会话提供经过核验的正确前置产物、仍有效决定和未决事项，保留完全相同的后续用户请求、工具和剩余预算，去掉中间插单。短对照也失败，先审任务难度与评分；长失败短成功，则进一步核上游快照与模型实际输入。若要区分“上游产物错”和“长历史干扰”，另取同一个代理自产快照，分别保留长历史或仅附已公开的有效状态说明。事先标记，这是诊断干预。
4. **确认有信号再展开。** 统计各配对中关键依赖、切回恢复和合格交付成本发生变化的方向与大小，对照同策略重复的变动。检查差异有没有被场景难度、缺失快照、脚本泄露、缓存污染或失败早停解释。用错误变体检出的差异只证明检查器灵敏；实际策略差异须由真实轨迹提供。若基础 CLM 从未产生有效编辑，可在同一组开发题新增两组：预注册窗口占用越线提醒和每请求提醒。分别固定阈值分母、是否重复提醒、提醒文本与注入位置；120K 仅用于复现原有同窗口设置。仍测不出差异时记录零结果，保留表现相同的题，不按哪组获胜筛题。
5. **再扩到约 50 题。** 进入扩题须同时满足真实依赖经反事实检查成立、独立评分可重放、输入压力和实际消费事件可审计，以及至少一个预设质量或成本维度出现可复查的配对差异；小样本只作测量能力判断。若两次重复不足以区分波动，就增加相同配置的重复或独立会话，再判断。扩题按已覆盖的领域×依赖形式×证据来源补空缺，保留持续主线和没有切换的题。开发题、同模板变体、同一业务材料及近似脚本按家族分组，冻结独立留出集、计费表与报告方案后再做正式对比。跨模型或跨 Harness 用独立表，仅在共同设置内解释策略差异；样本足够时按会话家族做配对区间估计。

**本版状态。** 当前完成的是文献与数据核查以及试跑设计。样题业务数值是拟制的校验例。真实沙箱、冻结评分器及策略配对运行属于下一阶段；本设计没有预设哪种策略应当获胜。
