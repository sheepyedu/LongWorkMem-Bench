# W1 · 跨月采购关账、项目结算与奖金交付

W1 考察财务运营助理能否在一次持续九轮的会话中，把早期批复、已报送的账和实际发送记录用于后续工作。**每个模型对每个种子只跑一场**，默认使用八级题面和 v4 百分制评分。两个预留种子上的既有交付按现行规则复评后，DeepSeek 均分 **63.30**，千问均分 **45.84**，两款模型各领先一场。

## 办公环境

代理用 Claude Code 操作一个隔离的办公室。每轮开始才收到新委托和当期材料，以前留下的工作簿、脚本和笔记可以继续使用。以开发种子 431 为例，九轮先后开放 183 份业务文件和 126 封来信，业务文件中有 51 个 Excel。采购和工时材料含 288 个订单行和 754 行原始工时，混有旧签件、重复导出和其他日常文件。每场使用同一份人事批复，种子决定其他业务数字、部分岗位和授权编号。

共享盘 shell 每次调用占一批 ERP 作业额度，同一批可以运行脚本、处理多个文件并核对结果。拟稿和投递分别通过邮件工具办理。正式文件写入 `out/` 即提交，宿主在每轮截止时取快照，并保存邮件实际投递时的附件。评分代码、参考解和后续材料均留在代理视野之外。

## 九轮如何接续

| 轮次 | 用户委托与应交成果 | 后续依赖 | ERP 批数 | 过程分 |
|---|---|---|---:|---:|
| 1 | 接手跨库采购。关联采购、收货和发票，交初版底表、待认领及寄售逐单清单。 | 留存凭证迁移通知和主管口头签发的六组预留岗位与额度。 | 4 | 3 |
| 2 | 接收六月替换页、退回及认领材料，更新关账版；按当日工单发首询并留真实回执。 | 这一版成为六月实际报送基准；同批人事邮件规定 E07 从 7 月 16 日起转岗。 | 5 | 4 |
| 3 | 冻结上轮实际报送的底表、待认领和寄售原表；凭证移库前保存人事索引，办理 6 月 30 日预留。 | 七月售后和工资分别需要六月原凭证、当时有效的工牌和合同。 | 3 | 3 |
| 4 | 管理层临时开会。用六月报送版制作差异简报和优先跟进清单。 | 会后签发有期限的临时代办，变更范围仅覆盖指定项目与争议类型。 | 3 | 3 |

| 7 | 按早期人事批复、合同和双签调班单折算工时，交工资明细、待核票据、调班表及可重算工资簿。 | 项目池、个人金额和归属都要正确；财务改工时或池额后仍须自动重算。 | 6 | 3 |

## 怎样评分

九个过程点共 **30 分**，按当轮交付和可验证操作取证。四项业务结果共 **70 分**，每项内部按完成比例给部分分。

| 业务结果 | 满分 | 宿主取证 |
|---|---:|---|
| 采购关账 | 18 | 核对六月报送、七月当前账、寄售认领和售后冲抵，并检查六月定版能否持续调阅。 |
| 工资结算 | 20 | 联合核对员工、项目、工时和实发金额，检查项目总额，并用 Calc 在独立副本上实际改工时、改池额。 |
| 资金交接 | 12 | 对照两个银行截点、书面授权、实际收件人及附件范围，核验真实处置。 |
| 跨期预留 | 20 | 四个办理日各核对 36 案的项目、岗位、批文、处置、预留额和变动额，并检查历史申报留存。 |

例如，遗漏第四轮会议简报，只损失该轮的 3 分。第八轮少报的金额会影响当天成绩；如果第九轮根据真实少报数正确追调，仍可取得相应信用。宿主可用 `--details` 查看每个评分点的证据。

## 模型成绩与 token 用量

以下四场由 Claude Code 2.1.314 在 Docker 办公环境中完成，使用相同的业务材料、工具和每场 350 次上游请求上限。1733、2671 是两个预留数据种子。v4 直接复评与当前单版本题面一致的历史九轮轨迹，表中 token 来自这些轨迹原有的模型 API 回执。评分复算本身没有新增模型调用。

## 复现与查证

安装 Python 3.12 依赖、LibreOffice Calc 和 Claude Code，构建隔离办公镜像并在宿主配置相应提供方凭证。下列第一条命令启动一场完整九轮会话，第二条读取该场成绩。比较模型时，各用一个新的输出目录运行相同种子。

```sh
python -m w1.pilot runs/w1/w1-deepseek --seed 1733
python -m w1.advanced runs/w1/w1-deepseek --details
python -m w1.pilot runs/w1/w1-qwen --seed 1733 --model qwen3.8-flash
python -m w1.paired runs/w1/w1-deepseek runs/w1/w1-qwen
```
