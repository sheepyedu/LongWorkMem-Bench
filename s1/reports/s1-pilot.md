## 运行条件

2026-11-27，以 Claude Code 2.1.314 驱动方舟 `deepseek-v4-1-flash-261017`，使用上游默认推理设置、相同种子 31。自然会话每条上限 150 次上游请求，四条短对照每条上限 30 次。每个实例使用独立配置目录、会话 ID 和 SQLite 牌桌，八轮沿用同一会话。两种版本各自在开幕公布对子或同色装备加成失效。标准席位的预算和发牌相同，私人席位保留各自的选择。以下数据来自实际回执，缓存输入已计入累计输入。

## 隔离、评分与故障复核

- **可见界面。** 核对了逐次实际发给上游的系统提示、用户消息、工具清单和返回值。完整和短对照会话只注册 `mcp__table__observe` 和 `mcp__table__act`。Docker 牌桌中只有游戏与 MCP 代码，只挂载本场竞技场数据库，断网且根文件系统只读。每次启动先在一次性桌面检查握手、读写和资源接口关闭；每轮同时检查真实 Claude 初始化报告。公开的游戏关口、得分和牌型说明供正常比赛使用。五组评测权重、评分代码、另一版本、宿主路径和 API 凭证没有进入被测模型请求。
- **如何逐条查。** 每条轨迹对照用户委托、全部助手表述、工具参数与返回、宿主实际动作和轮末快照。按工具调用 ID 和内容对账，按提供方回执统计请求。主观动机无法从文字确定。能实证的是假设的装备、错数的牌、夸大的推断和无效指令；未发现伪造实付、伪造正式出牌、读取评分器或篡改回执的证据。业务总分和表述错误分别记账。
- **评分判别力。** 两版均有持续装、一次装两种正确构筑，分别能达到 16、15 分，均拿满 30 分；两个版本的合格装备集合互斥。实际错误构筑可只拿 8 游戏分。离线负例中，只错一次邀请赛、回主赛首手和统一组锁定，得 53/100；两席只填草案而未锁定，配合其他真实赛果得 50/100。两项都是人为控制样本。付款可在输掉私人比赛后正常得分。损坏或缺失的宿主证据单独登记异常。
- **连通性测试。** 初次烟测因凭证注入和虚拟机挂载配置有误产生 9 次 401，无模型生成或游戏动作，排除在成绩之外。第二次 5 个推理回执和 4 个成功工具调用证明随机码被写入并正确读回；验收器却因笔记带有“交接代号”前缀误判。修复后按完整代号、真实写入与随后读回的相同笔记以及最终回报验收。原轨迹复验通过，全新烟测同样用 5 次请求、4 次操作通过。旧状态保留可审计。
- **用量和格式。** 针对带标签笔记、键顺序、UTF-8 BOM、CRLF、空行、无效 JSON、非法字段、篡改回执和缺失快照设置回归。修订 A 的第 40 次请求在适配层失败，仍有 35,578 输入、5,498 输出的上游回执，已计入用量。无效参数没有执行；后续成功请求单列。保留当次错误和快照，无需推测或自动修改模型生成的参数。

## 这道开发题目前能说明什么

标准商店能检验早期情报是否改变行动。当前种子中两种装备路线等价可解，模型得到情报后往往会反复把它写进笔记和交接回复；到期时还能看到自己先前的解释。所有赛季共用相同的少数牌面结构，实际出现的 11＋4 与 4＋11 路线都被评分器接受。这个种子适合做工具、规则切换和记忆策略的回归样本。自然成绩、真实请求间隔和是否发生压缩应一并报告。若以 30–70 分和更长历史作为难度目标，此开发种子需要另做难度校准；已有轨迹以冻结权重保留。下一批可在相同评分机制下加长有实际资源后果的赛程、加入有有效期的多条侦察，再先验证补全有效历史的每一版都可解。
