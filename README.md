# LongWorkMem-Bench

**面向超长工作会话的智能体上下文管理评测基准**

同一句“继续处理”，在两段不同的工作历史中，可能要求两种不同的行动。前期审批决定了谁可以收到附件，早先约定的时区决定了夏令时切换后的排期，勘察时看到的限宽标识决定了大件应从哪个岔口运出。LongWorkMem-Bench 拟通过这些可以核验的后果，研究智能体如何保留、更新和重新使用上下文。

**当前阶段为开发试跑。** W1 跨月关账和 S1 跨幕卡牌联赛已有公开开发实例、Claude Code 运行器和程序检查点。其余七个家族处于候选阶段。开发试跑用于验证环境、评分和难度，正式留出集与排行榜待建设。

## 运行 W1 跨月关账

W1 每个实例只运行一次。执行 `python -m w1.pilot runs/w1 --seed 1733` 后，一个 Claude Code 会话连续处理九轮委托，覆盖关账、会议插单、跨月预留、奖金计算和授权投递。默认使用八级办公材料与每会话 350 次请求预算。种子决定业务数据，同一实例面向所有模型使用同一份人事批复。

运行 `python -m w1.advanced runs/w1` 取得独立的百分制成绩。每轮一个过程点，九轮共 30 分；四项业务结果占 70 分，包括采购关账 18、工资结算 20、资金交接 12、跨期预留 20。评分在宿主核验截止快照、实际投递及工作簿重算。`--details` 可查看每项背后的核验记录。此前采用两版的成绩属于历史校准，见 [W1 难度与配对实验](docs/research/w1-difficulty.md)。

在 Python 3.12 环境安装 `requirements-w1.txt`，准备 LibreOffice Calc，可先运行离线测试。正式跑还需 Claude Code 和 Ark 凭证。终端在启动时隐藏读取密钥。见 [运行与验收指南](TEST.md) 和 [逐轮试跑审阅](docs/research/w1-pilot.md)。

## 运行 S1 跨幕卡牌联赛

八轮赛季包含侦察、两站主赛、临时邀请赛、返回主线、补给、双席报名和决赛清算。玩家通过牌桌查看和操作手牌、订单、装备和自己的笔记。每个种子使用固定的开幕侦察和租借牌，每款模型只需开赛一次。自由组则承接玩家沿途的选择。

在 Python 3.12 中运行 `python -m unittest discover -p 'test_s1*.py'` 可离线验证。正式会话可在断网 Docker 牌桌中运行，另有只从报名台开始的两种短对照。镜像构建、CLI 命令和逐轮取证方法见 [测试指南](TEST.md#s1-跨幕卡牌联赛)。四条完整会话、四条报名短对照的实测成绩与难度结论见 [S1 逐轨迹审阅](docs/research/s1-pilot.md)。

## 任务范围

| Domain | 主要交付 | 候选会话 |
|---|---|---|
| **Work** | 文件、表格、邮件及业务系统中的正确状态 | W1 跨月关账与奖金分配 · W2 招标澄清与定向发信 · W3 批量售后与缺货替代 |
| **Code** | 可运行、可跨阶段维护的软件改动 | C1 工单事件库 · C2 跨时区排期门户 · C3 需求预测与历史重放 |
| **Simulation** | 在文本可交互的持续环境中完成多阶段目标 | S1 跨幕卡牌构筑 · S2 局部可见的仓储迷宫 · S3 器材整备与批次召回 |

## 规模与评价

- **一题是一条完整会话。** 多数用户轮推进同一主线，也可以临时插入半相关或无关事项，再回到原任务。输入材料、工具反馈和业务状态逐步累积。
- **首版目标约 50 题。** 单题规划为几轮到十几轮用户交互、约 1,000–2,000 次模型请求、几十 M 至几百 M token 的累计输入（1 M = 100 万）。累计输入包含重复发送的历史，另记单请求峰值；具体长度和领域配比由试跑校准。
- **程序化检查点为主。** 在 Docker 沙箱内冻结文件、数据库及事件，分别评分阶段进度、首次返回主线时的恢复、最终交付和副作用。固定模型、Harness、工具与预算比较上下文策略，分项报告有效编辑、原生压缩、缓存、成本和耗时。
- **先校准题目。** 对关键存档分别运行“只给当前观察”和“补齐此前已公开的有效事实”两种短对照，再与完整会话比较。W1 工资存档和 S1 统一组商店均可进行短对照。

## 继续建设

1. 从九道候选题中选一个家族，写出一条来源明确、能改变后续结果的依赖，生成一个可重放的实例。
2. 为一个关键阶段准备可重置的初态、分轮消息、可验证的正确解与单点错误解。先在相同存档、相同预算下验证评分器。
3. 接入完整会话，记录实际请求与冻结快照。依据质量、上下文压力及成本修订题包，再扩展到其他家族。

公开示例中的检查点用于解释测量目标。正式留出实例、随机种子和答案应与开发示例分别管理。

S1 另有八轮器材交接题。领队需在有限交接簿中保留开幕底册、已批变更、撤回和各赛段的历史状态，后续订单在配发时才公布。主条件在第 4、7、8 班更换会话。仓单版在下单时提供可能过期的季前档案，可测量模型能否用早期授权纠正旧配置。四档样本规模、双模型配对与对照实验见 `docs/research/s1-memory-calibration.md`，运行命令见 `TEST.md`。

S1 连续跨区长赛季把各区八班穿插进同一个 Claude Code 会话。领队需要按赛区、队号和有效日期定位早期授权。混合赛固定 80 轮，8 个大区和 2 个小区。独立验证中，两个模型的平均每局输入分别为 114 万和 112 万 tokens，单次上下文峰值另计。运行方法见 `TEST.md`，实测口径见 `docs/research/s1-circuit.md`。

长赛季支持单独指定 `--models gpt-6.1-sol`，用 Claude Code 运行相同材料；路由使用 low 推理档。

长赛季每个种子只跑一个开幕版本。40 个收文轮登记指定队伍当时的配置，逐字段共计 30 分。40 个执行轮按实际配发和补办凭证共计 70 分。历史双版本实验仍按当时规则复现。
